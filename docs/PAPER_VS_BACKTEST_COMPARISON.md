# Paper vs Backtest Comparison

## Overview
The paper-vs-backtest comparison subsystem is a purely local analytical tool that measures the divergence between a simulated forward-walk "paper" run and a historical "backtest" run.
It aims to help researchers understand if their paper trading results align with historical expectations.

## Source Types
- `PAPER_RUN`: Simulates virtual paper trading results.
- `BACKTEST_RUN`: Historical backtesting results.
- `BASKET_BACKTEST_RUN`: Basket-level portfolio backtesting results.
- `SCAN_RUN`, `SIGNAL_FILE`, `CANDIDATE_FILE`: Snapshots for drift analysis.

## Matching Mechanism
### Trade Matching
Trades are matched heuristically using `symbol`, `timeframe`, `strategy_name`, and entry timestamps (within a configured `matching_tolerance_bars`).
Trades can be classified as:
- `MATCHED`: Found in both.
- `PAPER_ONLY`: Occurred in paper but not in backtest.
- `BACKTEST_ONLY`: Occurred in backtest but not in paper.

### Order/Fill Matching
Orders and fills can also be matched similarly to identify quantity and price disparities.

## Performance Gap Metrics
Metrics are generated by comparing total return, max drawdown, win rate, and profit factor.
- **Return Gap**: `Paper Return - Backtest Return`
- **Drawdown Gap**: `Paper Max Drawdown - Backtest Max Drawdown`
- **Win Rate/Profit Factor Gap**: Standard difference.
- **Trade Count Gap**: `Paper Trades - Backtest Trades`

## CLI Examples
```bash
python -m usa_signal_bot comparison-info
python -m usa_signal_bot comparison-run-latest --latest-paper --latest-backtest --write
```

This comparison is **NOT** a validation of live broker execution. It only compares two local simulations. It does not guarantee future performance and is not investment advice.
